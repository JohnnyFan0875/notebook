# Dashboard Design

`notebook_temp/output` 裡的 `Dashboard Design Concepts` 最值得保留的不是某個工具畫面，而是 dashboard 本身的設計原則。單張圖表重點在「看懂」，dashboard 重點則在「幫決策者在同一畫面完成判斷」。

## Dashboard 不是圖表拼盤

一個好的 dashboard 應該讓使用者快速回答明確問題，例如：

- 這週的關鍵指標有沒有異常？
- 哪個區域或產品線拖累了總表現？
- 我現在應該追哪一個 drill-down？

如果畫面只是把很多圖塞在一起，讀者反而更難找到決策重點。

## 設計前先定義三件事

1. **Audience**: 誰要看？主管、分析師、營運、還是客戶？
2. **Decision**: 他們看完要做什麼決策？
3. **Cadence**: 這是每天看、每週看，還是即時監控？

## 常見版面層次

- 最上層：核心 KPI 與警示
- 中層：趨勢、分群比較、區域或品類拆解
- 下層：細部明細、篩選條件、補充表格

## 好 dashboard 的原則

- 視覺層級清楚，重要資訊先看到
- 色彩有語意，例如紅色只用在警示或異常
- 同類型指標使用一致刻度與格式
- 篩選器不要比內容更搶戲
- 每張圖都應該服務同一個問題脈絡

## 常見錯誤

- 同一頁放太多圖，卻沒有閱讀順序
- 每張圖都很漂亮，但彼此沒有敘事連結
- KPI 沒有比較基準，例如去年同期、目標值、預測值
- 顏色太多，導致重點不明
- 手機或投影顯示時字太小、圖太密

## 與一般資料視覺化的差別

單張圖表可以專注說明一個洞見；dashboard 必須處理「監控 + 比較 + 導航」三件事，因此更需要一致性與信息層級。

## 小結

如果你是在做日常監控、商業回顧或決策支援，先想 dashboard 需求，再回頭決定每一張圖怎麼畫，通常會比先畫圖再拼版面更有效。
