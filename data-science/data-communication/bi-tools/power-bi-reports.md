# Power BI 報表 (Power BI Reports)

報表層的兩件事：怎麼組織與導覽（report vs dashboard、bookmark、drillthrough、tooltip、Q&A），以及怎麼設計（讀者、漸進揭露、主題、無障礙、行動版）。通用的 dashboard 原則見 [Dashboard 設計](../dashboard-design.md)。

## 三種交付物

| | Dashboard（Service 中的磚） | 互動式 report | Paginated report |
| --- | --- | --- | --- |
| 一句話 | 看現在 | 問問題 | 固定輸出 |
| 頁數 | 單頁 | 多頁 | 依資料分頁 |
| 互動 | 少 | 多：篩選、drill、連動、導覽 | 少（參數） |
| 適合 | 快速監控關鍵指標、使用者停留時間短 | 深入探索、使用者會一路追問、有大螢幕與好的輸入裝置 | 列印、正式文件、像素級精準排版（Power BI Report Builder 製作） |

## 報表的結構與導覽

report 不是圖表倉庫，而是有結構的分析應用：使用者要知道自己在哪一層、下一步能去哪裡。

| 原則 | 做法 |
| --- | --- |
| 一頁一主題 | 每頁回答一組集中的問題 |
| 先總覽再深入 | 第 1 頁：整體 KPI 與主要發現 → 第 2 頁：原因拆解 → 第 3 頁：地區 / 客群 → 第 4 頁：診斷或行動 |
| 導覽一致 | 用 Page / Bookmark Navigator 自動建立導覽按鈕，與頁面名稱和順序同步 |

### Bookmark 是狀態

bookmark 不是瀏覽器書籤，而是報表某個預先定義的狀態，可包含：目前頁面、篩選、slicer 選擇、視覺的選取狀態、排序、drill 位置、物件是否顯示。它保存的是一組互動脈絡，不只是畫面快照。

按鈕 (button) 可以 drillthrough 到新頁、導覽到指定頁、套用 bookmark、開啟網址；有 default / on hover / on press / disabled 四種狀態，可分別設定文字、圖示、外框與填色，讓使用者知道哪些可點、已選或暫時不可用。符號與 emoji 可以當輕量提示，但應該輔助語意，而不是取代語意。

### 使用者互動

| 互動 | 作用 | 適合 |
| --- | --- | --- |
| Drill-down | 沿同一個階層往更細層看 | 年 → 季 → 月、地區 → 城市 → 門市 |
| Drillthrough | 帶著某個資料點的脈絡跳到另一個細節頁 | 從某客戶跳到該客戶的完整檔案 |
| Cross-filtering / highlighting | 點一個視覺，其他視覺隨之篩選或重算 | 看某分群對其他指標的影響 |
| Slicer | 使用者自己縮小範圍；有相對日期、階層、清單等形式 | 同一報表給不同角色重複使用 |
| Custom tooltip | 滑鼠移過時顯示另一個 tooltip 頁面（本身不可互動） | 補充脈絡，不佔主畫面 |
| Explore | 不改壞既有報表的臨時探索 | 正式報表前的試問；格式能力有限，不能當最終交付 |

互動要服務明確的問題（哪個客群流失最嚴重？哪個地區拉動 KPI 最多？），而不是展示工具功能；所有視覺互相連動但使用者不知道為什麼，報表反而更難用。

### Q&A

Q&A 讓使用者用自然語言提問，系統產生對應的視覺，支援自動完成、拼字修正、預覽答案、提示不認得的字詞。

| 用法 | 例子 |
| --- | --- |
| 用欄位或 measure 名稱提問，`by` / `grouped by` / `where` 表達分組與篩選 | `Actual Amount by Cost Center grouped by Date` |
| `as {visual}` 指定圖表類型 | `... as table`、`as treemap` |

Q&A 好不好用取決於模型的語意：欄位與 measure 用業務友善的名稱（`Actual Amount` 而非 `amt_act`）、設定同義詞（不要重疊）、提供範例問題。Teach Q&A 中，名詞通常對應欄位、形容詞通常對應篩選。它適合加速探索，不能取代報表作者。

## 報表設計

先設計讀者，再設計視覺：使用者第一眼要看哪個 KPI？接著最可能追問什麼？在桌機、投影還是手機上看？

### 漸進揭露 (Progressive Disclosure)

從抽象到具體、一步步揭露資訊，只有使用者需要時才顯示更細的內容。很多報表難用，是因為首頁塞滿細節、使用者找不到下一步、摘要與明細混在同一層。

在 Power BI 中常用 **bookmark + selection pane + button** 做多狀態頁面：bookmark 記住狀態、selection pane 控制視覺的顯示 / 隱藏、button 在狀態間切換，讓同一頁在摘要與細節之間切換。注意隱藏視覺可能重設篩選，切換後要確認篩選行為仍符合預期。

### 版面與視線

| 版型 | 視線 | 適合 |
| --- | --- | --- |
| Gutenberg | 左上 → 右下 | 一般報表首頁 |
| Z | 明確起點與終點的 Z 字路徑 | 資訊密度較低的頁面、行動版 |
| F | 先掃上方，再沿左側往下找 | 文字或清單較多的頁面 |

每頁要有明確的焦點 (focal point)，關鍵視覺不要和次要資訊搶注意力；三分法 (rule of thirds) 提醒不要機械式地把所有重點塞在正中央。重點是使用者能否在幾秒內抓到這頁的主角。

### 主題 (Themes)

主題是整份報表的格式預設：顏色、圖示集、視覺格式、字型、字級。用主題而不是逐一修改視覺，才能維持一致、新增視覺時不破壞風格。主題檔是 JSON，可以版本控制、只改局部、在多份報表共用（View → Themes → Browse for themes / Save current theme；小調整用 Customize current theme）。

| 主題原則 | |
| --- | --- |
| 字夠大、易讀 | 第一個主題色是主色 |
| 顏色容易區分、數量少 | 檢查色覺差異 (CVD) 下仍可分辨 |
| 淺色主題配較飽和的顏色 | 深色主題配較亮的色調 |

### 無障礙 (Accessibility)

| 面向 | 做法 |
| --- | --- |
| 顏色 | 不要只靠顏色傳達狀態；同時用形狀、標籤、圖示、位置；避免紅綠搭配；用 CVD 模擬工具（如 Coblis）檢查 |
| 對比 | 一般文字對比度至少 4.5:1，大字 3:1；背景圖常拉低對比，要克制使用 |
| 螢幕閱讀器 | 視覺補 alt text（可固定，也可用 DAX 動態產生）；提供「以表格顯示資料」 |
| 鍵盤與互動 | 不是所有內容都能用鍵盤順暢操作；重要洞察不要只藏在複雜互動或純視覺編碼裡 |

無障礙要一開始就當成版面與編碼的限制條件，放到最後補通常只能局部修補。

### 行動版版面 (Mobile Layout)

行動版是不同的閱讀情境，不是把桌面版縮小。

| 能做 | 不能做 |
| --- | --- |
| 選擇要顯示的既有視覺並重新排列 | 在行動版檢視中新增視覺或圖形 |
| drillthrough、slicer、cross-filter 照常運作 | 桌面版隱藏的視覺不會自動出現 |
| bookmark navigator 做按鈕式導覽 | 完整編輯視覺格式 |

| 行動版原則 | |
| --- | --- |
| 關鍵指標放最前面 | 同一屏不超過約四個主要指標 |
| 顯示單位適度摘要（K、M） | measure 名稱必要時縮短 |
| 用 Z 版型安排閱讀順序 | 檢查同一視覺在 web 與手機上的方向都合理 |

手機上某個視覺不好讀時，優先改版面或換視覺，而不是硬塞。
