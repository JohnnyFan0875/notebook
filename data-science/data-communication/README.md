# Data Communication

這個模組整理資料工作中「把分析做對、也把問題說對」的核心能力。它不只關心圖表怎麼呈現，也關心一開始怎麼把模糊的商業需求翻成可以被資料回答的分析問題。

Key point: 很多分析失敗，不是因為模型不夠好，而是因為一開始問錯問題，或沒有把商業語境、資料限制與決策需求對齊。

## Recommended Learning Path

1. [Forming Analytical Questions](./forming-analytical-questions.md): 學會把 business question 轉成 analytical question，避免一開始就做錯方向。
2. [Communicating Data Insights](./communicating-data-insights.md): 問題定義完成後，再把洞察整理成受眾看得懂、記得住、願意行動的內容。
3. [Reports and Presentations](./reports-and-presentations.md): 當訊息已經清楚後，再把它包裝成合適的 written report 或 oral presentation。
4. [Dashboard Design](./dashboard-design.md): 當結果要組成一個決策畫面，先理解 dashboard 的版面、層級與互動原則。
5. [Tableau](./tableau/README.md): 如果需要把資料連接、計算欄位與互動式 dashboard 落地到 BI 工具，可以再往下看 Tableau 工作流。

Tip: 如果你常遇到「需求很大、但不知道從哪個資料切入」，先回來檢查問題是否已經具備明確對象、衡量方式、時間範圍與可行的分析方法。
