# 資料溝通 (Data Communication)

把分析做對，也把問題問對、把結果說清楚。很多分析失敗不是因為模型不夠好，而是一開始問錯問題，或結果沒有以讀者能理解、信任、採取行動的形式交付。

## 建議順序

```
形成分析問題 → 溝通結果（報告、簡報、可重現報告）→ Dashboard 設計 → BI 工具（選讀）
```

## 筆記

| 筆記 | 內容 | 回答的問題 |
| --- | --- | --- |
| [形成分析問題](forming-analytical-questions.md) | 業務 / 研究問題 → 分析問題、釐清需求、四種分析類型 | 這個問題要怎麼改寫成資料能回答的問題？ |
| [溝通分析結果](communicating-results.md) | 讀者分析、單一訊息、資料故事、可信度、報告與簡報結構、可重現報告 | 有了結果之後怎麼說、用什麼格式交付？ |
| [Dashboard 設計](dashboard-design.md) | 目的、版面層級、KPI 與比較基準、篩選與互動 | 多張圖怎麼組成幫人做決策的畫面？ |
| [BI 工具](bi-tools/README.md) | Power Query、Power BI 模型與 DAX、Power BI 報表、Tableau | 要交付互動式報表給非程式使用者時，工具怎麼用？ |
